# v1.2.0 Windows verification checklist

The automated suite proves geometry, schema compatibility, catalogue integrity
and build layout. It cannot prove anything about a packaged Windows application,
because the environment that runs it has no Windows, no display server and no
Electron binary. This checklist is the part that needs a real machine, and it is
the only evidence that answers the question *"do both Gold Series designs
actually work in crshhx?"*

Run it against the artefacts produced by the `windows-release` packaging job for
tag `v1.2.0`. Record results in the table at the end; a line that was not run is
reported as not run, never as passed.

**Needs:** Windows 10 or 11 x64 · both executables · their published sizes and
SHA-256 digests · a second display if you have one (for the mixed-scaling checks)
· the two reference images the designs were measured from · an export file made
by 1.0.0 or 1.1.0, if you still have one.

## 1. Artefact integrity

- [ ] Filenames are exactly `crshhx-crosshair-studio-setup-1.2.0.exe` and
      `crshhx-crosshair-studio-portable-1.2.0.exe` — no spaces, correct version.
- [ ] Byte sizes match the packaging run's log.
- [ ] `Get-FileHash <file> -Algorithm SHA256` matches the digest on the release
      page, for **both** files.
- [ ] The release carries exactly two assets, and the v1.1.0 release still
      carries its own two, unchanged.

## 2. Executable metadata (what `rcedit` stamps — a Linux build cannot)

For each executable: right-click → Properties → Details.

- [ ] Product name: **Crshhx Crosshair Studio**
- [ ] Product version and File version: **1.2.0**
- [ ] Company/description fields are not blank or placeholder text.
- [ ] The file icon is the crshhx icon, at every size Windows renders it
      (16 px in Explorer's details pane, 48 px in medium icons, 256 px in extra
      large icons) — a missing size shows as a blank or generic square.

## 3. Installer path

- [ ] Double-clicking installs with **no prompts** (one-click; the directory
      chooser was deliberately removed).
- [ ] It launches when the installer finishes.
- [ ] Desktop and Start Menu shortcuts exist, both named
      **Crshhx Crosshair Studio**.
- [ ] It installed per-user (no UAC elevation for a standard account).
- [ ] The tray icon appears and is a real icon, not a blank square — this is the
      `extraResources` copy on disk, not the one embedded in the exe.

## 4. Portable path

- [ ] Runs from an arbitrary folder, including a USB stick or a path with spaces.
- [ ] Same metadata and icon as the installer build.
- [ ] User data still lives in the roaming application-data directory, not next
      to the exe: a library created from the portable build is visible after
      moving the exe to a different folder.

## 5. Gold Series in the application

- [ ] Pro Crosshairs shows a **Gold Series** category, and it contains exactly
      two designs: Arc Crown and Compact Mark.
- [ ] Each carries the small gold **Gold** chip — gold text on a dark gold
      hairline, restrained: no glow, no gradient, no animation.
- [ ] Each shows its tier badge (**Competitive-inspired**) and its attribution:
      a fan recreation from public reference imagery of MrSavage's crosshair, not
      an official preset, no endorsement implied.
- [ ] The standard catalogue is unchanged: the other eight categories still hold
      their five designs each, forty in total, and none of them moved, renamed or
      changed appearance.

## 6. Arc Crown — geometry against the reference

- [ ] Exactly **four** arcs, on the diagonals, with the four cardinals open.
- [ ] Arc ends are **flat (butt caps)**, not rounded.
- [ ] The gaps between arcs are equal, and the pattern is centred on the
      crosshair's centre point.
- [ ] Colour is the reference vermilion `#dc583e` — sample it from a screenshot
      with a colour picker rather than judging by eye.
- [ ] Centre dot is `#28f953`, circular, and sits exactly at the centre.
- [ ] Ring radius to stroke thickness reads as the reference's ratio (28 : 4).

## 7. Compact Mark — geometry against the reference

- [ ] A green cross, monochrome `#6af469`.
- [ ] **Hollow centre** — the four inner edges form the aiming point.
- [ ] **No centre dot** and **no outer outline** (no black or white halo).
- [ ] Proportions read as length 12 : gap 5 : thickness 4.

## 8. Live overlay — the part a preview cannot prove

- [ ] Selecting Arc Crown applies it; **F10** toggles the overlay and the arcs
      appear on screen exactly as previewed — same segment count, same gaps, same
      colours, same centring.
- [ ] Same for Compact Mark.
- [ ] **F9** cycles presets and both designs survive the cycle.
- [ ] The overlay stays click-through and does not steal focus from a game or a
      fullscreen application.
- [ ] Screenshot the overlay over a bright scene and a dark scene: neither design
      disappears, and no arc is clipped at any edge.

## 9. Persistence across restarts

- [ ] Apply Arc Crown → quit from the tray → relaunch → still applied.
- [ ] Favourite Compact Mark → relaunch → still favourited.
- [ ] Save an edited copy of either through the preset manager → relaunch → the
      copy is present with its edits, and the shipped design is untouched.
- [ ] Weapon-slot assignments still point at the right presets after a restart.

## 10. Display scaling — the matrix that cannot be automated here

Set Windows display scaling, then for **each** of 100 %, 125 %, 150 % and 200 %:

- [ ] The overlay is centred on the selected target display.
- [ ] Arc Crown's four arcs are still four arcs of equal span — no segment
      appearing or disappearing, no gap collapsing.
- [ ] No clipping of the reticle at the window edge, and no visible offset
      between the preview and the overlay.
- [ ] The reported scaling in the monitor list matches Windows (for example
      `150%`), and a display that does not report a rate says so rather than
      inventing one.

Mixed and changing topology:

- [ ] Two displays at **different** scaling (for example a 150 % laptop panel and
      a 100 % external monitor): Target Monitor puts the overlay on the chosen
      display, correctly centred, on both.
- [ ] Unplug and replug the second display, and change resolution and scaling
      while running: the overlay repositions rather than staying at stale
      coordinates (this is a 1.1.0 feature — check it for regression).

## 11. Legacy compatibility

- [ ] Import an export file written by 1.0.0 or 1.1.0: it imports completely, and
      the informational note names the version that wrote it
      (`Exported by crshhx 1.0.0.`). Nothing is refused, nothing is half-applied.
- [ ] Export from 1.2.0 and re-import: round-trips with no loss, and the new file
      is stamped `1.2.0`.
- [ ] Every pre-existing **full-circle** design renders exactly as it did in
      1.1.0: Spread Ring, Halo Ring, Target Ring, Wide Ring White, Arena Ring.
      Schema v3 defaults to a complete circle, so these must be pixel-identical
      in behaviour — compare against a 1.1.0 install side by side if you can.
- [ ] Existing custom crosshairs, folders, favourites, game profiles and
      weapon-slot settings are all still present after upgrading over 1.1.0.

## 12. Designer — segmented-circle controls

- [ ] On any ring design: set segments **4**, arc span **40**, rotation **45** →
      the result matches Arc Crown's arrangement.
- [ ] Segments **1** (or span **360**) → a plain complete circle: the legacy
      path, not a 1-segment arc.
- [ ] Rotation turns a **segmented** ring, and leaves a **complete** circle
      unchanged — a full circle is rotation-invariant, as it always was.
- [ ] Outline and inner-outline settings still apply per segment, and scaling the
      design scales the whole ring proportionally.
- [ ] Out-of-range input is clamped or repaired with a visible message, never
      applied silently.

## 13. Regression sweep (unchanged features, quick pass)

- [ ] Background mode: closing the window hides to the tray; overlays, hotkeys
      and slot switching keep running; quitting is explicit from the tray menu.
- [ ] 4:3 / stretched-resolution compensation still positions the reticle.
- [ ] ADS morphing and dynamic firing bloom still behave (bloom needs firing in a
      game or the in-app demo — a static preview cannot show it).
- [ ] Crosshair Academy's ten tutorials still load and their demos still render.
- [ ] The ban-safety audit page still opens and reports.
- [ ] Undo/redo, clipboard and zoom shortcuts still work in the editor.

## 14. Upgrade and uninstall

- [ ] Installing 1.2.0 over an existing 1.1.0 install upgrades in place and keeps
      the library, settings and slot profiles.
- [ ] Uninstalling removes the application but **keeps user data** in the roaming
      profile (`deleteAppDataOnUninstall: false` is pinned by a test; verify the
      behaviour anyway).
- [ ] Reinstalling after that uninstall finds the library intact.
